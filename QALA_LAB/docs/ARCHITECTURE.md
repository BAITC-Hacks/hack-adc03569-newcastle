# QALA LAB — архитектура

## Шекаралар

Бұл жоба ұйымдастырушының синтетикалық деректерімен жұмыс істейді. Нақты Астананың жағдайын бағаламайды, саясаттарды рейтингтемейді, болашақ ықтималдығын есептемейді. Қолданушының орнына бес шараны таңдайтын оптимизатор жоқ.

```text
Браузер: web/index.html + style.css + app.js
   │  тек measure_id, district_id, question
   ▼
server.py: маршрут, JSON, origin/Host, өлшем шектеулері
   ├── engine.validate → қате болса HTTP 422, score:null
   └── engine.simulate → Decimal, 50 ұяшық, паспорт
         ├── интерфейс / CSV / JSON / басып шығару
         ├── engine.compare → A/B қайта есептеу, B−A
         ├── engine.sensitivity → бөлек тәжірибе, Score жоқ
         └── evidence.facts_for → белгілі фактілер
                  ▼
              ai.explain
                  ├── кілт бар → OpenAI Responses API → fact_id жоспары
                  └── кілт жоқ/қате → ашық белгіленген offline шаблон
                  ▼
              validate_plan → server-side факті сөйлемдері
```

## Модульдер

| Файл | Жауапкершілік | Не істемейді |
|---|---|---|
| `app/dataset.json` | Дереккөзден алынған аудан, көрсеткіш, шара, ереже | Нақты қала статистикасы ретінде ұсынылмайды |
| `app/engine.py` | Тексеру, Decimal есептеу, ledger, паспорт, салыстыру | AI шақырмайды; еркін мәтінді орындамайды |
| `app/evidence.py` | Есептен KK/RU фактілер құрастыру | Жаңа өлшем, сан, тұрғын пікірі қоспайды |
| `app/ai.py` | Дәлел ID-ларын таңдау және тексеру | LLM жазған еркін сандарды қабылдамайды |
| `server.py` | Жергілікті HTTP API және статикалық файлдар | Қоғамдық production сервері емес |
| `web/app.js` | UI күйі, енгізу, көрсету, импорт/экспорт | Соңғы ресми санды өз бетімен есептемейді |

## Неліктен Python + vanilla JavaScript?

Тәуелділікті азайту — қорғауда жоба іске қосылуы үшін жасалған инженерлік таңдау. Python стандартты кітапханасындағы Decimal, JSON, urllib, unittest және HTTPServer жеткілікті. Браузерде сыртқы пакет пен CDN жоқ. Бұл барлық жобаға арналған әмбебап шешім деген мәлімдеме емес.

## Дерек жолы

1. Клиент тек шешімдер жібереді; импортталған `score` сенімді кіріс емес.
2. Сервер схема, аудан, дәл 5 шара, бюджет, қайталану, бағыт және сәйкессіздікті тексереді.
3. Әр әсер лаг коэффициентімен көбейтіледі. Қалалық шара бес ауданға таралады.
4. Фиксацияланған синергиялар қосылады. Барлық қосындыдан кейін clip қолданылады.
5. Түпнұсқа салмақтар мен формула қолданылып, тек API шекарасында JSON санына айналады.
6. Ledger әр ұяшықтың толық арифметикасын сақтайды. `exact_after`, `exact_score` ондық жол ретінде де беріледі.
7. Шешімдер канондық сұрыпталады. Датасет/engine хэштері мен нұсқасы сценарий паспортын қалыптастырады.

## LLM келісімшарты

Жауаптың схемасы: `status`, `sections[{heading, fact_ids}]`. `heading` пен ID тек белгілі тізімнен алынады; қосымша өрістерге жол берілмейді. Модель шектеулері мен M11 шарасының екі жақты әсері қажет болса сервермен қосылады.

Бұл тәсіл сандардың есептен шыққанын қамтамасыз етеді. Дәлелдердің сұраққа сәйкестігі мен толықтығын адам тексеруі керек. Құрылымдық валидация семантикалық мінсіздікке кепіл емес. Кілтсіз режим LLM емес. Нақты API интеграциясы кілтпен бөлек тексерілуі қажет.

## Сенім және қауіпсіздік

Шектеулер: localhost әдепкісі; statics whitelist; сыртқы origin/Host тексеруі; 64 КБ JSON; 600 таңба сұрақ; 25 секунд upstream timeout; минутына 8 түсіндірме; `.env` жарияланбайды; HTML escaping; CSP. Бұл толық қауіпсіздік аудиті емес. Auth, TLS, көп пайдаланушы сақтау, production сервері, желілік мониторинг кейінгі кезеңге жатады.

`localStorage` жеке браузерде; JSON тасымалданады. Жергілікті URL басқа компьютерге автоматты қолжетімділік бермейді. SHA-256 fingerprint қолтаңба немесе блокчейн емес.

## Қосылған жорамалдар

Аудан схемасы географиялық карта емес. «Мерзім зертханасы» лагқа 0–3 тоқсан қосатын бөлек сезімталдық тәжірибесі; қалған параметрлер мен синергия тұрақты, ресми есеп/паспорт өзгермейді. Жаңа Score, ықтималдық, тұрғын саны жасалмайды.

## Келесі нақты қадамдар

Алдымен тірі API мен команданың ноутбугінде іске қосуды тексеру. Содан кейін ғана auth, өндірістік сервер және тұрақты сақтау. Нақты қалалық деректерге көшу үшін дерек иесімен қолжетімділік, анықтамалар, күндер мен модель коэффициенттерін тексеру керек; осы синтетикалық әсерлерді шынайы болжамға тікелей көшіруге болмайды.
