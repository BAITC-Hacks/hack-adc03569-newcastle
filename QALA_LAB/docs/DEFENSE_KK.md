# Қазылар сұрақтарына дайындық

## 1. Жобаңыздың нақты ерекшелігі қандай?

Біз тек нәтижені көрсетпейміз: барлық 50 көрсеткіштің есеп жолын, дәлелге байланған түсіндірмені және қайта есептелетін паспортты бірге береміз. «Әлемде бірінші» деген тексерілмеген мәлімдеме жасамаймыз; ерекшелік — осы бөлшектердің бір тексерілетін жұмыс жолына бірігуінде.

## 2. AI қайда қолданылады?

`app/ai.py` OpenAI Responses API-ға есептен жасалған фактілерді жібереді. LLM сұраққа қатысты `fact_id` тізімін қайтарады. Сервер тексерілген факті сөйлемдерін шығарады. Сандық есеп `app/engine.py` ішінде және AI-ға тәуелсіз.

## 3. Кілт жоқ болса, бұл AI ма?

Жоқ. Кілтсіз түсіндірме — ережелік шаблон. UI оны нақты белгілейді. LLM интеграциясының болуы мен осы сәтте тірі LLM қолданылуы екі бөлек факт. Қорғауда сәтті live жауапты көрсетіңіз немесе offline екенін айтыңыз.

## 4. Бұл толыққанды агенттік жүйе ме?

Жоқ. Прототипте есептеу модулі, дәлел құрастырушы және бір LLM шақыруы бар. Оларды «көп агент» деп әсірелемейміз. Күрделілік емес, нақты орындалған логика мен тексерілгіштік маңызды.

## 5. Неліктен AI-ға бірден «баллды есепте» демейсіздер?

Ережелер детерминдік: лаг, синергия, салмақ және шек дәл орындалуы керек. Сондықтан есепті кодқа бердік. Құжаттың «Роль ИИ» бөлімі де осы бөлуді талап етеді. LLM сандары қорытынды есепке кірмейді.

## 6. Галлюцинацияны толық жойдыңыздар ма?

Толық жойдық деп айтпаймыз. Жауап тек белгілі ID-ларды қолданады; сөйлемдер серверде құралады, белгісіз ID қабылданбайды. Бірақ LLM дәлелдерді сұраққа орынды және толық таңдамауы мүмкін. Семантикалық тексеру адамда қалады.

## 7. Неліктен Decimal?

Берілген ондық салмақтар мен халық үлестерін аралық дөңгелектеусіз есептеу үшін. API сандары интерфейсте дөңгелектелуі мүмкін, бірақ бастапқы есепке қайта берілмейді. Толық жазылым `exact_score` және `exact_after` ішінде бар.

## 8. Бес бағыттан міндетті түрде бір-бір шара керек пе?

Датасеттің егжей-тегжейлі §4 ережесі: дәл бес шара және бір бағыттан ең көбі екі. Сондықтан кемінде үш бағыт қамтылады, бірақ бес бағыттың әрқайсысынан біреу алу міндетті емес. Бұл түсіндіру README-де ашық көрсетілген.

## 9. Төрт шешім немесе артық бюджет болса не болады?

Толық ресми нәтиже берілмейді. HTTP 422 және себептер тізімі қайтарылады. Редактордың аралық валидациясы бар, бірақ ол толық сценарийге айналмайынша Score жасамайды. UI бастапқы модельді бөлек белгілейді.

## 10. Лаг пен синергия қалай есептеледі?

Негізгі әсер `толық_әсер × (8−лаг)/8`. Синергия — бөлек тұрақты бонус, лагқа көбейтілмейді. Барлық қосындыдан кейін ғана көрсеткіш 0–100 шегіне келтіріледі.

## 11. Критикалық шек 40-ты қамти ма?

Жоқ. Шек — қатаң `<40`. Әр аудан мен көрсеткіш жұбы жеке саналады. 40 дәл мәні шегерім тудырмайды; бұған жеке тест бар.

## 12. Барлық шара оң әсер бере ме?

Жоқ. Түпнұсқада M11 қауіпсіз өткелдер шарасы B2-ні арттырады, бірақ T1-ге теріс әсер береді. Код екі әсерді де сақтайды; түсіндірмеде бұл екі жақтылық жоғалып кетпеуі үшін міндетті факт бар.

## 13. Бұл нақты Астана статистикасы ма?

Жоқ. Ұйымдастырушы дайындаған синтетикалық деректер. Аудан схемасы да географиялық карта емес. Көрсеткішті нақты тұрғын санына, теңгеге немесе болашақ оқиғаларға тікелей аудармаймыз.

## 14. Сезімталдық зертханасы түпнұсқада бар ма?

Дәл осы 0–3 тоқсан қосу механизмі — команда қосқан мүмкіндік. Ол бөлек белгіленген. Тек бір лаг өзгереді; қалған параметрлер мен синергия тұрақты. Ресми паспорт өзгермейді; тәжірибеде қосымша Score және ықтималдық жоқ.

## 15. Паспорт хэші нені дәлелдейді?

Бірдей шешімдер, нормаланған датасет және код нұсқасы бір идентификаторға әкеледі. Ол қайталап есептеуге көмектеседі. Хэш цифрлық қолтаңба, авторлық сертификат немесе өзгермейтін блокчейн емес.

## 16. Импортталған файлдағы сан өзгертілсе ше?

Сервер дайын баллға сенбейді: тек шешімдерді алып қайта есептейді. Паспорт/сан сәйкес келмесе UI ескерту береді. Есептің сенімді кірісі — жарамды шаралар жиынтығы мен сервердегі модель.

## 17. Қандай тест орындалды?

105 unittest әдісі Linux/Python 3.13.5 ортасында өтті. Оның ішінде 1000 жарамды сценарий тәуелсіз float есебімен салыстырылды, 120 permutation бірдей нәтиже берді. Бұлар 105-тен бөлек 1120 тест әдісі емес: екі тесттің ішкі жағдайлары. Нақты тізім `TEST_REPORT.md` ішінде.

## 18. Қандай нәрсе әлі тексерілген жоқ?

Осы жеткізу кезінде нақты API кілтімен сұрау жіберілмеді. Windows/macOS орындауы, Docker build/run, GitHub CI және production deployment орындалған жоқ. Chromium UI тексеруі жергілікті файлдар және нақты API-ға көпір арқылы өтті; орта саясаты қалыпты URL навигациясын бұғаттады. Команда ноутбугінде толық қалыпты іске қосу қажет.

## 19. Неге React немесе үлкен backend framework емес?

Қорғауда орнату тәуелділігін азайту үшін Python стандартты кітапханасы мен vanilla JavaScript таңдадық. Осы прототип үшін жеткілікті. Бұл стек барлық масштабқа дайын деген сөз емес. Қоғамдық сервиске өндірістік сервер, auth, TLS және сақтау қосылады.

## 20. Екі сценарийден қайсысын жүйе таңдайды?

Жүйе таңдауды пайдаланушыға қалдырады. Салыстыруда бірдей бастапқы деректерден есептелген B−A айырмалары көрсетіледі. Рейтинг, саяси ұсыныс немесе автоматты «ең жақсы жоспар» жоқ.

## 21. Өнімді кім және қалай сынай алады?

Синтетикалық сценарийді түсінуге арналған оқу/талдау прототипі ретінде: бес шешім енгізу, әсерін тексеру, сценарийлер айырмасын түсіндіру. Шынайы пайдаланушы зерттеуі жасалмаған; қолдану құндылығы әзірге дәлелдеуді қажет ететін өнімдік гипотеза.

## 22. README не үшін соншалықты толық?

Тапсырма PDF-інің 3-бетінде README және қайта орындауға 25 балл бөлінген. Сондықтан іске қосу, модель, шектеулер, мысал, тест және қорғау материалдары бірге берілген. Бұл 25 баллды автоматты аламыз деген кепіл емес.

## 23. Нақты қалаға көшу үшін не керек?

Рұқсат етілген актуалды деректер, көрсеткіштердің анықтамалары, жауапты мамандармен әсер коэффициенттерін тексеру және белгісіздік моделі қажет. Синтетикалық параметрлерді сол күйінде нақты қала болжамы ретінде қолдануға болмайды.

## 24. Құпия кілт қайда?

Тек сервердегі `.env` немесе environment variable ішінде. Браузерге берілмейді, статикалық жолмен ашылмайды, `.gitignore` арқылы еленбейді. Қорғауда немесе репозиторийде кілт көрсетілмеуі керек.
